# 华恋对局数据服务

独立 Python 3.12+ / SQLite 实现，无运行时第三方依赖。`web/` 是实际查询页面，原 `docs/design/karen-mod-observatory/` 保留为离线示例。

## 上传协议

部署生成两个持久的 192 位随机路径：页面前缀与上传端点。公网入口与联机服务共用 `8443`，根路径返回 404；后端仅监听回环 `42767`。路径、页面密码和内部读取凭据保存在远端私有配置中，不进入 Git。

客户端配置 `artifacts/telemetry-deploy/client-endpoint.json` 仅包含 `{"Url":"<完整上传URL>"}`。项目文件将其作为 `KarenTelemetryEndpoint.json` 嵌入构建；未配置时跳过上传，不回退旧后端。上传地址是公开客户端协议的一部分，不能视为身份认证秘密；页面地址和内部读取凭据不进入客户端。当前按用户确认采用凭长链接访问，无需额外密码；知道页面链接即可读取、下载原始数据，玩家 ID 保持不变。

客户端在对局历史生成后，直接向 `<上传URL>` 发送一次 HTTPS POST，Content-Type 为 `application/json`，正文为完整 UTF-8 RunHistory JSON。不需要先申请 session，不使用 Bearer 或内置长期密钥。

现有 r6 APK 的两步流程继续兼容：`POST <上传URL>/session` 仍接受原先的 `sha256` / `bytes` 清单，返回带 `upload_token` 的废弃协议响应，r6 随后提交正文可以正常接收。该返回值只是兼容标记，没有认证、授权或防重放含义；服务端不再维护令牌表，新客户端不调用此入口。既有数据库中的历史对局和旧元数据表保持原样。

所有记录继续标记 `verification: unverified_client`，不验证 Mod 或玩家身份。随机上传地址可被客户端提取，只用于减少盲扫；格式校验和预算限制持续执行。

| 状态 | 含义 |
| --- | --- |
| 201 | 已收新对局 / 旧 r6 兼容 session 响应 |
| 200 | 内容相同的重复对局 |
| 400 | JSON 或历史结构无效 |
| 409 | 同一平台、种子、开始时间和玩家集合已有不同内容，保留原记录 |
| 413 / 415 | 正文过大 / 媒体类型不符 |
| 429 | 频率、并发或每日收集预算到限 |
| 507 | 数据库容量到限 |

同局身份按平台、种子、开始时间和去重玩家集合计算，不把不同玩家的同种子开局合并。内容哈希忽略 JSON 键顺序。首次收到的有效记录保持不变，不静默覆盖冲突。没有前几层过滤，早期死亡与放弃都保存。

## 数据与统计

- 保存完整结构和缺失状态；只剔除 `karen_shine_current` / `karen_shine_max` 以及对应 SavedProperty 项。终局牌组和 `karen_shine_exhaust_cards` 独立保留。
- 原始下载保持 64 位整数精度；供浏览器展示的超大整数转字符串。
- 原生 `card_choices` 混有商店和遗物选牌。其条目只计“原生选牌记录”，不冒充免费奖励。缺少 `was_picked` 保留未知，不补 false。
- 只有显式 `choice_kind: free_reward` 且结果为布尔值的条目进入奖励选取率；当前原生客户端不额外生成此来源标记，所以普通上传的选取率为“—”。新增来源采集前，不推断奖励分母。
- 曾持有按席位/模型去重，结合终局、耗尽、获得、移除、变牌和明确选中证据；华恋开局四类模型取当前角色定义。历史版本若更换起始牌，需维护对应版本定义，不能宣称所有历史版本均精确重建。
- 默认排除前 5 层放弃，只影响统计；早期死亡保留，其他放弃计入未胜。结果筛选仅作用于对局列表，卡牌属性筛选不改变覆盖率分母。
- 时间按首次接收时间筛选。列表每页 20 局，列表 CSV 导出当前页；卡牌 CSV 导出筛选后的行。统计流式读取，最多显示 4,096 种模型，超限明确提示，原始记录仍可查询。
- 114 张当前华恋卡牌属性与缩略图从项目模型和简中本地化生成；其他未知模型以原始 ID 展示。

## 部署与防护

`install.py` 在已约定的独立 release 目录执行。只管理自身服务、两个独立 nginx include 及自身备份/监测；父 HTTPS、IP 证书和续期由联机任务维护。安装更新保留路径、密码和数据库。

- 页面与读取 API 当前凭随机长路径访问，回环后端仍核对 nginx 注入的内部凭据。安装参数 `--page-access link` / `--page-access password` 可切换，选择持久保存在远端配置，后续更新保留；未指定的新部署默认密码模式。上传端点不能读取数据。
- 上传与旧 r6 兼容入口共享单 IP 及全局各 30 次/分钟预算；全局上传连接最多 2，正文上限 8 MiB，兼容清单上限 1 KiB。滚动 24 小时最多 2,000 条新对局，数据库预算 1 GiB。
- 读取单 IP 20 次/秒、全局 40 次/秒；后端并发最多 8。服务非 root，256 MiB 内存、50% CPU、32 个任务上限，仅可写自己的数据与日志目录。
- 关闭路径访问日志，保留不含正文、凭据的应用错误日志；无 CORS 放行。随机长路径减少盲扫，不能替代认证、限流，也不能抵御占满带宽的攻击。
- `karen-observatory.service` 自动启动与失败重启；`karen-observatory-backup.timer` 每日在线 SQLite 备份并保留 7 份；`karen-observatory-monitor.timer` 每分钟检查健康、2 GiB 可用磁盘、900 MiB 数据库预警和 48 小时备份新鲜度。失败在 systemd 状态/日志中可查，不包含站外通知。
- 服务错误日志交给独立 logrotate 规则，按天/1 MiB 阈值检查，保留 7 份压缩；备份与原数据库在同一主机，尚不具备异机灾难恢复。

发行目录通过 `current` 符号链接切换；nginx 校验失败会恢复自身 include 和旧链接。回滚旧服务版本时须评估它的协议，不回滚数据库内容。服务上线前应运行本目录定向测试，不需要启动游戏。

## 定向验证

```powershell
python -m unittest discover -s tools/telemetry-server -p test_app.py -v
node --check tools/telemetry-server/web/app.js
```

`build_assets.py` 仅生成图片时需要 Pillow。`smoke.py <私有access.json>` 在指定部署创建一条合成测试记录并将 ID/种子写入本地证据；验证完按证据定点清除，不是常驻数据导入工具。严禁把测试副本算作正式样本。

两步协议阶段验证：9 项服务测试在 Windows 与 Ubuntu 通过；12 项外网可信 HTTPS 检查通过；正式/测试版上传源码编译均为 0 错误。两份原生历史先在本地临时 SQLite 往返通过；用户明确授权后，匿名化测试副本也经外网 HTTPS 接收、查询通过，19 项原生 `was_picked: false`、64 位 ID 与空耗尽堆结构保留，单次令牌重放被拒绝。四条测试对局已定点清除，线上与当日备份均为 0 局。浏览器通过回环验证代理检查线上页面，核对桌面/390 像素、表/图、显式详情、楼层联动和图片；无剩余闪耀显示。没有以编译或合成数据代替真实对局完成上传的结论；未执行完整游戏矩阵。
