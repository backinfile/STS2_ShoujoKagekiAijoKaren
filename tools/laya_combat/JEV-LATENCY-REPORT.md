# 每步延迟诊断与修复

2026-09-21。用户正在运行脚本时只读诊断，没有停止进程，也没有发送游戏动作。性能测试另外使用合成样本调用官方Jev API。

## 基线

当时 `logs/jev-decisions.jsonl`：从上次POST完成到下一次决定，中位数7.522秒；从决定到校验及POST完成，中位数0.071秒。唯一合法动作下一步间隔1.019秒。三次本地GET为46.4、33.9、32.9毫秒。

DNS测得0.007秒及低于0.001秒；无显式系统HTTP代理。一次不带密钥的官方接口curl探针：TLS完成4.394秒，首字节4.690秒（HTTP403）。这不是模型推理测试，但确认连接阶段本身耗时较高。

三个假设：重复HTTPS连接开销、API服务端耗时、固定1秒等待。对同一个合成请求建立连接并复用，得到首次TLS2.630秒、请求到首字节0.382秒；后续0.319和0.331秒。证据指向重复握手是主要开销，并非本地游戏API或两个串行模型请求。正反顺序问题原本就在一次API请求内批量发送。

## 修复

原 `urllib` 请求路径每次建立HTTPS连接；改为标准库 `http.client.HTTPSConnection` 长连接。响应完整读取后保留连接，服务端关闭后下一次重新建立；连接异常时关闭并停止，不重试已发送请求。仍使用TLS证书验证和固定官方域名，拒绝重定向。保持策略、候选、正反序批量问题和动作后1秒等待不变。

增加分段耗时字段用于后续核对。44项测试通过，包括连接复用、不重放失败请求和拒绝重定向。
