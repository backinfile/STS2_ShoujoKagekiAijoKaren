# 战士进阶0实测

2026-09-20，英文游戏，正式版 v0.107.1，Laya multilingual，CPU。

## 设置

战士初始10张卡牌，80血。开局选择 Booming Conch，仅在精英战触发，本次测试为普通战斗。对手为两只 Corpse Slug，26/25血。战斗动作全部由脚本执行，无人工代选；不开启药水候选，本场没有药水。

沿用固定英文通用策略，SHA256 为 `445a97083277ae3941c7dbcd25e7c124c8f808898bfc8256fff238b4df96065a`，全场保持一致。

v4首次尝试在出牌前因候选区超限停止。v5只修改输入格式：目标使用状态中可查的敌人ID；移除候选区重复算术提示；完全相同且仅索引不同的手牌合并规则说明；相同算术摘要合并列出动作引用。全部合法动作仍各自保留，扩展字段或费用等不同的牌不会合并。并非与华恋v4相同输入条件下的对照实验。

## 结果

- 第9回合获胜，30次决策和30次POST均成功。
- 80血开战，击杀前46血，燃烧之血回复6血后52血；本场实际损失34血，战后净损失28血。
- 23次模型决策，另外7次仅有结束回合这一合法动作。正反顺序的首选仅5/23次一致。
- 1次仍有可打牌时提前结束回合：第6回合剩2能量、4张可打牌。
- 最高输入985 tokens，没有再触发1024上限；复杂战斗仍可能超限。
- 23项单元测试通过，新增检查确保合并描述不会合并动作或忽略不同的扩展状态。

## 暴露的问题

1. 第1回合先 Strike 再 Bash；按当前显示规则，先施加易伤再攻击可多造成伤害。策略中的增益/减益顺序原则没有被稳定执行。
2. 第2回合已有10格挡、敌方意图总伤害8，仍花1能量追加5格挡。第6、9回合敌方无攻击意图时也打了防御。共3次防御的即时防伤增量为0。
3. 第6回合可继续攻击却提前结束，延长战斗。
4. 算术摘要只是基础数值，尚未计算目标易伤等修正。第9回合敌人8血且易伤，Strike显示6伤害但实际可致死；摘要会低估。这是输入信息质量问题，不能把数值摘要当成准确结算。

这证明执行链路能完成战士战斗，但单场胜利不代表策略可靠或角色适配结论。后续优先评测出牌顺序、边际防御和已知修正后的伤害；策略文本继续固定，避免逐卡加入专用打法。

本机原始记录（忽略文件）：`logs/ironclad-v4-start.json`、`logs/ironclad-v5-live.jsonl`、`logs/ironclad-v5-result.json`。游戏停在奖励界面，奖励未领取。

### 具体发现

- 第3场第7回合，敌人8血、无格挡，手里有足够费用的 Bash 和两张 Strike。模型先打两张 Defend，余下1费只能打一次 Strike，敌人剩2血；随后多承受4伤害，第8回合才击杀。可打牌不提前结束的指标改善，并不代表能找到斩杀。
- 4场共12次防御的即时防伤增量为0。这个指标按当前意图和格挡计算，不代表所有场景下该动作都绝对无用；本次仍反复出现明显的攻防分配问题。
- 第4场有 Plating，先前的基础算术不能规划跨回合格挡与输出效率。该场从26血开始，死亡同时受前三场累积损血影响，不能把它当成满血独立测试。
- 顺序一致性仍低，不能将平均概率或熵指标当成可靠性/胜率。

本次观察到同一局前4场3胜1负；这不是独立随机样本的75%胜率，也不是正常选牌、用药策略下的整局表现。保持初始卡组和不用药水是本次隔离战斗决策的测试条件，会限制后续强度。

优先改进方向仍是离线评测斩杀、出牌顺序和边际防御，完善已知伤害修正的事实摘要，并用标注数据验证/训练模型。此次没有按失败局面改写固定策略。

原始日志为 `logs/ironclad-v5-fight2.jsonl` 至 `fight4.jsonl`，各场起止快照为对应 `-start.json` / `-result.json`。复核命令：
