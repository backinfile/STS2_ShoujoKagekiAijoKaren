# Jev 结构化决策验证

验证版本：`jev-1.13.0`。测试输入为四份已有英文战斗快照，不连接或操作游戏。完整响应位于被Git忽略的 `logs/jev-v8-comparison.json`。

## 实现变化

- 每次决策重新构造结构化 `state`，候选动作及代码计算结果使用独立字段。
- 数字计算留在代码；未知能力和触发器明确标记，不把基线数值声明为确定结果。
- 默认用三道并行Choice问题分别比较生存、推进、效率，再以固定权重合并概率。
- 默认模型固定为 `jev-1.13.0`，并加入保守的输入预算保护。

## 快照结果

| 快照 | 单题模式 | 复合模式 | 结论 |
|---|---|---|---|
| 合成6血敌人 | 6伤攻击 | 6伤攻击 | 两者都识别安全斩杀 |
| 8血 Sludge Spinner | Bash | Bash | 两者都选择斩杀 |
| 过量格挡场景 | Strike → `CORPSE_SLUG_0` | Strike → `CORPSE_SLUG_0` | 两者均避免继续堆无即时价值的格挡 |
| 双 Corpse Slug | Bash → `CORPSE_SLUG_0` | Bash → `CORPSE_SLUG_1` | 动作一致，目标分歧；两只敌人状态接近，复合效用差距仅0.0215 |

复合模式输入分别为2316、4903、4550、7483 tokens；单题模式为1661、3968、3723、6024 tokens。复用TLS连接后，两种模式都约0.35–0.60秒；三道问题在同一个请求中并行计算。复合模式提供可审计的维度分布，但输入成本高约24%–39%，因此保留 `single` 模式用于持续A/B评估。

另对当前实际游戏的第8层选牌状态做了一次只读决策，没有执行动作。`jev-1.13.0` 在69/80生命、九张候选牌和确认选项中选择升级 Flame Barrier，复合效用0.523；首次连接耗时6.75秒，输入6842 tokens。该检查确认新流程能处理实际非战斗选择，但单次选择不能证明长期策略质量。
