## 用户反馈：录像最后卡住

原始 MP4 停帧检测复现失败：`freeze_start=7.866667`，随后从 `9.033333` 再次停帧；伤害数字和战场停止更新。此缺陷存在于字幕合成前，不能归因于成片编码。

临时探针记录到：正常游戏时间、`Engine.TimeScale=1`、`SceneTree.Paused=false`、房间仍可处理，ProcessFrames 每半秒增加约 30，但 FramesDrawn 长时间不增加。加长录制后，状态接口最终返回 rewards。说明逻辑正常结束，最小化窗口的渲染更新停滞，MCP 读取到了旧画面。

对照仅改变录制窗口状态即可恢复：录制前切为普通窗口，不最小化，奖励界面出现后再停止录制。尝试过的 MCP 强制绘制修改已撤回；最终复测使用原 MCP 源码 `2d2a4c5`，不需要修改卡牌演出或游戏结算逻辑。临时探针已从源码移除，开发环境已恢复无探针 DLL；MCP 试验分支和工作树已清理。

- 正式版原片约 11.80 秒：检查通过，`freeze_starts=[]`，状态确认 rewards。
- 测试版原片约 11.83 秒：检查通过，`freeze_starts=[]`，状态确认 rewards。
