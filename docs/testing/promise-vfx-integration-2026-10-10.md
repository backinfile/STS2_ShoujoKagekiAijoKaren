# 新约定牌堆与已有卡牌特效的交互适配

2026-10-10。用户确认再生产 V6 后，先将 `codex/stage-reproduce-vfx` 快进合并到 main（`add4cf0`），随后直接在 main 处理这一批交互。用户进一步明确：调整已有卡牌特效与新牌堆特效的衔接，保留已有演出。

## 改动

- 共用进出牌位置改为绘制塔的实际平台入口。原来的局部位置 `(-95,-160)` 与新塔口 `(-95,-119.5975)` 有偏差。
- 《空虚》生效后的 Draw 与约定牌堆共用进牌收束和取牌星光跟随；使用实际抽牌堆 `Icon` 的中心。取牌沿用原生 NCard 动画，星光轨迹由 HUD 前层绘制。
- 位置查询与取牌跟踪分开。查询目标位置不再改变进出方向，取牌方向由原生工厂提供的旧牌堆决定，避免依赖延迟同步后的星点状态。
- 《星光指引》从手牌节点、抽牌堆图标和弃牌堆图标取得画布坐标，沿同一颗库存星进入轨道。保留金色边框和手牌清理。
- 《约定之塔桥》每帧跟随当前塔口或 Draw 图标；保留已确认的桥体、追光、流光及实际自动出牌时序。
- 入牌收束增加一次性完成保护，并在 NCard 被对象池复用时停止操作旧模型的视觉节点。

规则、费用、目标、伤害、模式切换、原生抽牌及自动出牌结算不变。燃烧、过去与未来、觉醒形态和齿轮原有演出使用同一套移牌接线。

## 双版本定向实测

游戏使用本项目归档的隔离副本：正式版 v0.107.1 / 端口 15637，测试版 v0.111.0 / 端口 15638。每次启动临时加载只读观察探针与后台窗口保护，结束后移除，并恢复设置及 MCP 配置。窗口采样中前台次数和恢复显示次数均为 0。操作、截图、录像均通过 KarenSTS2MCP，无 Computer Use。

| 实际操作 | 正式版 | 测试版 | 核查 |
| --- | --- | --- | --- |
| Karen 新开局，坠落选择防御 → 约定之塔取回 → 打出防御 | 通过 | 通过 | 指定脚本 `tools/test_promise_visuals.ps1`；手牌中防御 3→2→3，原生可打出 |
| 缩放、翻转、旋转、非等比缩放、位移 | 通过 | 通过 | 上述脚本 `-TransformChecks`，塔口、直立方向和尺寸检查 |
| 新的一天 → 打击、行动、勇气打击、整手交换 | 通过 | 通过 | 普通 / 空虚各一组；卡牌本体、下一张牌、衍生牌和批量进出 |
| 星光指引收集手牌、抽牌堆及弃牌堆闪耀牌 | 通过 | 通过 | 普通 / 空虚；模型对应库存星，原手牌节点清理完整 |

主检查共 32 个定向场景（每版 8 类 × 普通/空虚），另有两版新开局专项和再生产回归。每次移牌保存操作前后截图，并在动画结束后执行 `karen_check_hand`；额外读取库存星的卡牌身份集合，空虚模式核查前后两层及屏幕范围。

两版最初的《昨天夜空的光辉》测试夹具只有一张弃牌，游戏自动选择而测试程序等待选牌框，故夹具失败。改为两张候选后重测通过；不是游戏选牌故障。

本轮按用户要求不运行完整矩阵。同版本多人三种 Karen 主客组合及原版角色对照、多人同步和恢复流程**未测**；清单中未列为实测牌的项只做公共调用路径核查，不宣称逐卡实机全覆盖。
