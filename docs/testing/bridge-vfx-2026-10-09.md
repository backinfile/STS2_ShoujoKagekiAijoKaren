# 约定之塔桥：实现与定向实测

2026-10-09。用户确认实施重新设计的“双塔接通”方案，并明确不要进行完整测试。本轮仅检查当前卡牌，未执行 `test_dev_matrix.ps1 -Suite full`。

## 实现

- 新增短暂的后景舞台布景：白色双塔、横向滑入的红白桁架、接通闪光和沿桥依次点亮的舞台灯。采用程序绘制的平涂结构，未生成或剪辑 TV 视频。
- 正常速度在 0.62 秒接通后调用原有自动出牌命令；大型布景约 1.3 秒消失。Fast 的等待和动画按同一比例缩短；Instant 与无交互模式不创建特效节点。
- 原有 X＋1、升级 X＋2，以及“先批量移到 Play，再依次自动打出”的规则不变。未修改 `PromisePileCmd`。
- 用 `BeforeCardAutoPlayed` 产生实际出牌追光，作用范围仅覆盖当前塔桥的异步结算。嵌套塔桥临时接管视觉作用域，`finally` 恢复；不增加选择、抽牌或伤害操作。
- 空虚模式复用原生抽牌堆自动出牌及洗牌；牌源光指向抽牌堆。空牌源只短暂点灯，不创建桥体或虚假卡牌。
- 节点从属于创建时的战斗和出牌者；房间失效、战斗结束时清理，声音同时停止。
- 新增两段程序合成的舞台机械声音，生成脚本为 `tools/vfx/generate_bridge_sfx.py`。无 TV 音轨采样，录制保留实际游戏声音。

造型、出处与未核实的原片细节见[资料与设计](../design/rare-vfx/bridge-source-research-2026-10-09.md)。

## 定向结果

以下项目在正式版、测试版均完成：

- **正常 X＝2**：预置防御、打击、防御，原生历史确认按该顺序实际自动打出三张，约定牌堆 3→0；观察到一次桥体和三次追光，结束后节点数为 0。
- **空牌源 X＝0**：只打出塔桥本身；一次短点灯，零次追光，牌源仍为空。
- **升级 X＝0**：实际打出两张，第三张防御留在约定牌堆；追光数为 2。
- **空虚 X＝2**：抽牌堆两张、弃牌堆一张。原生流程完成取牌和洗牌，三张依序自动打出，抽牌堆为空；一次来自抽牌堆的桥体、三次追光。
- **强制中断**：在塔桥入场时用开发者命令切换战斗，旧节点清理，新战斗没有旧自动出牌继续执行。
- **手牌一致性**：保存并查看各阶段前后截图，待原生移牌动画结束再执行 `karen_check_hand`；模型数与可见手牌节点均一致，无 missing、unexpected 或意外牌堆图标。
- **录像**：正常模式实际游戏画面，1280×720、30 fps，H.264＋AAC；MCP 确认 `audio_source=game_process`。逐帧联系图确认入场、接通、退场和后续出牌，未用设计预览代替游戏录像。

## 日志及测试过程中的问题

- 测试版最终轮在载入存档阶段记录一次 Godot `Invalid Task ID`，位于开始布置塔桥测试之前，与此前测试中记录的同类现象一致；本轮没有诊断或修复它。
- 早期测试版强制切换战斗时出现两次原生 `NCard` 重复回收日志。延长辅助发牌/移牌动画的收尾等待后，塔桥中断和原版 Havoc 中断对照均未复现，最终定向轮也未再出现。证据表明该现象与测试准备/切换的时序有关，尚未定位原生内部的根因，不宣称修复了卡牌池。
- 正式版记录瀑布巨兽音乐事件找不到的提示；没有 `ERROR`、`Exception` 或 `SCRIPT ERROR`。录像中仍保留实际卡牌与新增机械音效。
- 初期辅助脚本曾误按文本解析手牌 JSON，节点计数器也曾未被 Godot 调用；已分别改为 JSON 解析和 `SceneTree.ProcessFrame` 订阅。空虚牌源准备改为明确等待辅助异步任务完成。这些失败记录保留在 `artifacts/bridge-vfx/*-attempt`。
