# 闪耀耗尽衔接与塔灯可读性（2026-10-10）

## 对反馈的调整

上一版闪耀耗尽在同一帧隐藏卡牌并显示完整星点，卡面与星光之间缺少过渡。普通闪耀牌现在在原位用约 0.28 秒淡出，同时有少量暖色光屑向中心聚拢；星点随之渐亮，牌面完全消失后才开始沿原有路径飞行。星点由 21 调至 17，抵达后的淡出也使用平滑曲线。燃料已爆散的牌面不会在这一步重新显示，卡牌节点回收前恢复原透明度。

上一版塔灯只有小灯点，在正常战斗缩放下不明显。这版把两层平台边缘连成暖色灯带，并让亮度沿灯带流动；两侧塔脚各有两个错时上行的亮点。保留原塔身画作、库存星光、计数及空虚图标规则，灯光仍处于角色后方。

## 验证范围

通过 KarenSTS2MCP 顺序运行隔离的正式版 v0.107.1 与测试版 v0.111.0，保持后台，未使用 Computer Use。此次只复测两项视觉调整及燃料衔接，不重跑全量矩阵。

逐帧观察结果：普通牌淡出期间位置误差为 0；正式版观察到 12 帧中间透明度，测试版 13 帧，最低透明度分别为 0.000055 与 0.001074。两版飞行阶段可见卡牌帧数均为 0，耗尽图标终点误差为 0。燃料牌面在爆散后的过渡与飞行中均未重新出现，没有重复原生消耗动画。8 个视觉场景的 26 次 `karen_check_hand` 均通过，燃料抽回手牌的节点透明度与可见性正常。另通过 `tools/test_promise_visuals.ps1` 验证两版新建 Karen 战斗中的《坠落》→《约定之塔》，移牌后均执行手牌核对，返回牌可以继续打出。

首轮在动画中另取了 MCP 截图；截图会短暂阻塞渲染，因此最终两版短过渡均改为连续录制，仅在前后取 MCP 截图，再从录像抽帧检查中间过程。演示使用测试版的连续过渡录像，未做慢放或合成动画。

首轮测试版燃料耗尽在最后淡出时出现一次 `Invalid polygon data, triangulation failed`。原因是星形顶点使用绝对屏幕坐标，半径趋近于零时顶点精度不足。现改为在单位坐标中生成星形，再通过绘制变换缩放；最终接近透明的亚像素帧也不再绘制多边形。两版耗尽场景均在修正后重新运行，首轮证据保留在 `stable-first-pass` / `beta-first-pass`，不与最终耗尽结果混用。

最终正式版日志无错误；测试版两次启动各有 2 条既有 `Invalid Task ID`，均发生在 Common 资源预加载内，栈为 `worker_thread_pool.cpp:418`，单独登记在核对报告。进入战斗后的本轮视觉操作无新增错误，星形三角化错误未再出现。测试窗口的前台与恢复显示采样均为 0；临时探针和后台守卫已移除，测试进程已退出。

两版构建均为 0 错误。全量、多人、存档恢复与 Instant 模式未测，不据此宣称通过。
