# 创意工坊特效 Mod 解包与制作流程

整理日期：2026-10-14。对象为《Slay the Spire 2》的五个创意工坊 Mod，用于选择 Karen 后续特效的制作方法。

这五个样本覆盖了透明序列帧、实时粒子、Shader、程序化运动和角色姿态复制。最有价值的共性是：**美术资源定义形状，场景组织层次，C# 根据真实游戏事件安排位置、时间和生命周期。** 复杂效果通常组合这几种方法，而不是只靠一种粒子系统。

本次取得了五份实际 Steam 发布包，解出了全部 4,378 个 PCK 条目，并反编译了五份 DLL；另取得 Lovecs、魔理沙的 GitHub 工程，复用了项目此前下载的储君工程。以下是静态资源与代码分析，尚未进行这些 Mod 的游戏内播放或双版本兼容验证。

## 下载与证据目录

研究根目录：[workshop-vfx-2026-10-14](../artifacts/reference-mods/workshop-vfx-2026-10-14/)。

## 储君特效的制作流程

源码与逐卡拆解见已有的 [18.储君特效Mod制作思路与分类](18.储君特效Mod制作思路与分类.md)。本次工坊包恢复的 45 个场景、16 个 Shader、1,210 张 PNG，与此前工程统计的规模一致；这不代表整个 DLL 或工程逐字相同。

### 从主动画到游戏事件

1. 将主运动制作成透明 PNG 帧序列。工坊资源能证明使用了预制帧，不能据此断定作者使用 AE、Blender 或其他工具。
2. 在 Godot 的 `SpriteFrames` 中排列帧、设置速度和循环方式，以 `AnimatedSprite2D` 作为主动画。
3. 加上 GPU 星点、尾迹、Shader 扭曲，以及 `StartPos` 等用于适配方向的辅助节点。
4. C# 通过 `CardFX` 或 `PowerFX` 描述单卡差异，复用持牌准备、取消恢复、播放和清理流程。
5. 攻击起势接在 `BeforeExecute`，每击接在 `BeforeDamage`；Power 则有施加、层数变化、触发和移除入口。
6. 峰值加入声效、曝光和震屏，尾部释放节点或恢复借出的星星。

### 三个可以直接研究的案例

- **Alignment**：42 张透明帧，场景 30 fps，末尾额外有空纹理帧。约 1.4 秒的主动画说明资源聚集与转换，得能量继续由原生命令执行。帧里的形状变化已被预制，实时控制主要决定出现位置和时点。
- **SevenStars**：七颗准备星排成北斗，每次真实伤害前消耗一颗，并给实际敌人播放短斩击。它把一次大的准备与七次小的命中拆开。
- **Supermassive / BlackHole / Pillar**：常驻主体由模型状态维持，成长、触发或发射只激活附加层。Power 移除或战斗结束再清理，比每次触发都重建全套动画更容易表现积累。

方向适配的核心是把场景里预制的起终点映射到真实起终点：按两条方向向量的长度比缩放，按角度差旋转，再平移到实际目标。等比缩放会同时改变宽度，因此超远距离未必适合直接拉长整组帧。

阅读入口：[CardFX.cs](../artifacts/reference-mods/sts2_regent_fx/Scripts/Vfx/Cards/CardFX.cs)、[CardVfxUtil.cs](../artifacts/reference-mods/sts2_regent_fx/Scripts/Vfx/Cards/CardVfxUtil.cs)、[VFXUtil.cs](../artifacts/reference-mods/sts2_regent_fx/Scripts/VFXUtil.cs)、[PowerTimingPatch.cs](../artifacts/reference-mods/sts2_regent_fx/Scripts/Patches/PowerTimingPatch.cs)。

**适合 Karen 的部分**：少数重型招式可用透明序列帧；约定之塔这类常驻物可借鉴建立、等待、激活、退场的分层。已有实时运输与抽牌表现适合继续使用真实目标坐标，不必都变成固定帧动画。

## 更多的角色特效的制作流程

这一份是“程序编排为主，预制帧为辅”。恢复资源有三组明显的帧序列：`star_appear` 61 张、`star_creat` 30 张、`star_shine` 61 张；另外有星体和轨道 Shader。复杂星阵不是全部画成动画，而是在 C# 中创建和调度。

### 敌人死亡动画

`CombatFeedbackCapture` 给 `Creature.InvokeDiedEvent` 做 Postfix。Dispatcher 确认死亡、识别敌人，并对同一对象同一帧做去重，然后由 `CombatFeedbackEnemydead.PlayAtEnemy` 找到死亡位置。

它缓存 `star_appear` 纹理，创建 Sprite2D，通过 `ProcessFrame` 与 `Time.GetTicksMsec()` 手工推进纹理。61 张资源中，播放从 **第 13 帧**开始，30 fps；若帧齐全，使用 48 张，名义时长 **1.6 秒**。前 12% 平滑淡入，后 60% 淡出。完成或节点失效时解除帧事件，根节点释放。

因此，“有 61 张图片”并不等于“每次死亡播放完整 61 帧”。真正的运行时间要从代码的起始帧、速度和结束条件算。

### 环绕星与选择动画

`OrbitAuraFeature` 持有主星、辅星、连线、前后层和选择动画状态。`PlayerCombatState.Stars` setter 的补丁触发数量刷新；拖牌时临时重排，取消或完成时恢复。Shader 给轮廓与轨道加细节，Tween 负责移动和退出。

它优先读取本地 Regent 的实际 Stars，读取失败时有 **7 星视觉回退值**。这说明反射兼容回退不能当作资源数的可靠依据。若用于 Karen 的约定牌堆，应该绑定真实卡牌身份与实际牌堆数量。

### 死亡与胜利是不同事件

每个敌人死亡可播放局部反馈；`CombatWon` 才依据房间类型记录一条普通、精英或 Boss 的胜利星。Dispatcher 延后两帧检查是否已经战胜，避免最后一个敌人的普通提示与胜利演出重复。`CombatEnded` 关闭环绕表现。

这一拆分比把所有表现都接到“造成伤害”更准确：每击、每次死亡和每场胜利有不同的视觉预算。

阅读入口：[死亡纹理播放器](../artifacts/reference-mods/workshop-vfx-2026-10-14/decompiled/3747579486/MoreCharacterFX.MoreCharacterFXCode.Features.CombatFeedback/CombatFeedbackEnemydead.cs)、[事件分发器](../artifacts/reference-mods/workshop-vfx-2026-10-14/decompiled/3747579486/MoreCharacterFX.MoreCharacterFXCode.Features.CombatFeedback/CombatFeedbackDispatcher.cs)、[环绕星控制器](../artifacts/reference-mods/workshop-vfx-2026-10-14/decompiled/3747579486/MoreCharacterFX.MoreCharacterFXCode.Features.OrbitAuraFX/OrbitAuraFeature.cs)。

**适合 Karen 的部分**：约定牌堆数量、闪耀状态等用模型驱动程序化布局，创建与消失叠短帧序列；需要区分一张卡耗尽、一个 Power 触发和一场战斗结束。

## 更多的动作与特效的制作流程

这个样本同时覆盖三条路线，不能把它概括成一个“播放动画包”。

### 攻击位移

`SimpleTeleportPatch` 跟踪 `AttackCommand.Execute`，拦截 `CreatureCmd.TriggerAnim`。命中角色和攻击条件后，它用替换的 Task 接入位移及原动画。角色节点的 `GlobalPosition`、朝向、缩放、透明度和回位状态由 Tween 与异步方法管理，并有超时与节点有效性检查。

其制作重点不是新增贴图，而是把已有角色的出招重新编排成接近目标、击打、回位。它使用 AsyncLocal 关联当前攻击，并介入通用攻击与动画流程，版本适配和多人并发的影响面较大。移位、原动画与回位的 Task 归属需要一起理解，不能只摘出其中一个 Prefix。

### 余像是姿态复制

`GhostSpawner.CreateGhostNode` 调用 **`body.Duplicate()`**，递归关闭处理与输入，读取原角色 Spine 的动画名与播放时间，让复制体停在该姿态。复制体沿 `GlobalTransform` 放置，Tween 控制漂移、回位和透明度。

它不是按每帧截图再上传纹理。`AfterimageEffect` 施放后的 1 秒活跃窗口用 0.1 秒间隔，其余时间用 0.2 秒间隔；相关生成路径检查 12 个残影的上限，并让主动残影短时间压制被动残影。另有不限量入口，所以 12 不能当作所有特效的全局上限。

这套方式能跟随皮肤与实时动作，但复制整棵角色节点、等待 Spine Ready、管理共享包装节点都需要成本。Karen 若使用，应限制为短促动作，并避免复制血条、交互和规则控制器。

### 华丽收场与子弹时间

- **华丽收场**使用 15 张 1920×1080 透明帧，场景速度 **12.5 fps**，名义时长 1.2 秒。C# 把场景放在视口中心，根据角色朝向镜像，并设置 1.2 秒删除 Timer。这是典型“整屏预制画面 + 运行时挂载”。
- **子弹时间**先识别 `BULLET_TIME` 出牌，再等待对应不可抽牌 Power；如果该 Power 已存在则立即启动。随后挂灰度与扭曲层，Power 移除、层数归零或退场时恢复。制作层面使用的是屏幕采样、颜色处理、波纹和动画速度管理。
- `DistortionFilter` 的 Shader 写在 C# 字符串里，采样 `hint_screen_texture`，计算围绕角色的波纹偏移，并组合色差和冷色处理。没有 `.gdshader` 文件不代表没有 Shader。
- **HitStop** 独立地保存 `Engine.TimeScale`、设为 0，用真实毫秒时钟控制结束，并在 `finally` 恢复。它影响全局时间，属于高影响的表现手段；不能仅凭清单的 `affects_gameplay=false` 推断不会影响联机时序。

阅读入口：[GhostSpawner.cs](../artifacts/reference-mods/workshop-vfx-2026-10-14/decompiled/3774274248/MeleeAttack/GhostSpawner.cs)、[AfterimageEffect.cs](../artifacts/reference-mods/workshop-vfx-2026-10-14/decompiled/3774274248/MeleeAttack/AfterimageEffect.cs)、[SequenceScreenEffect.cs](../artifacts/reference-mods/workshop-vfx-2026-10-14/decompiled/3774274248/MeleeAttack/SequenceScreenEffect.cs)、[BulletTimeEffect.cs](../artifacts/reference-mods/workshop-vfx-2026-10-14/decompiled/3774274248/MeleeAttack/BulletTimeEffect.cs)、[HitStop.cs](../artifacts/reference-mods/workshop-vfx-2026-10-14/decompiled/3774274248/MeleeAttack/HitStop.cs)。

**适合 Karen 的部分**：攻击前倾、短距离冲刺、有限残影和局部闪击。全屏滤镜、整个角色移位和全局停时应单独设计所有权与恢复机制，避免与已有舞台灯、卡牌输入和其他 Mod 互相覆盖。

## Lovecs VFX 的制作流程

Lovecs 是这组样本里最清楚的可复用特效模板：四类光环模板与四个一次性场景合计 8 个场景，主要采用 `GPUParticles2D`、`ParticleProcessMaterial`、曲线和图集。

### 先在场景里声明可修改的位置

1. 在 Godot 调整粒子数量、寿命、方向、速度、颜色和缩放曲线，得到 Default、Enchanted、Guard 或 Focus 的基本形态。
2. 给需要外部修改的属性添加 Marker 子节点。例如 `TintMarker` 指定颜色槽，`SpriteSheetMarker` 指定图集槽，`PowerScalingMarker` 声明强度范围。
3. 小 GDScript 只提供 Inspector 字段；运行时替换主要由 C# 的 `GdVfxMarkerAdapter` 与 `GdVfxStateReceiverAdapter` 执行。
4. 卡牌或 Power 用 Builder 配置颜色、Power 图标、图集、粒子大小和稳定 key，不必为每个 Power 复制整个场景。

Enchanted 的符号图集是 **25×1** 的粒子动画格子，不是 25 个独立 PNG 文件。这个例子说明“序列动画”也可以作为粒子图集使用。

### 再让真实 Power 驱动它

`PowerAuraApplyPatch` 的 Postfix 启动辅助任务，**先 await 原 `PowerCmd.Apply`**，再添加光环。`PowerAuraController` 绑定 `DisplayAmountChanged` 与 `Removed`；显示量更新时 Sync，移除时解绑并释放。

强度映射为：

```text
ratio = clamp(inverse_lerp(minAmount, maxAmount, DisplayAmount), 0, 1)
Emitting = Active && ratio > 0
AmountRatio = ratio
SpeedScale = lerp(minSpeed, maxSpeed, ratio)
```

这里主要改变粒子的数量比例和速度，不是把整组光环无限放大。`AuraCmd` 在角色 VFX 容器下建立锚点，根据 key 复用同一个光环；每帧更新位置。修改共享的粒子材质前会 Duplicate，并设为 `ResourceLocalToScene`，避免一个 Power 的设置污染另一个实例。

一次性 `NLovecSimpleVfx` 则在 Ready 重启粒子或动画，按 `LifetimeMs` 延后释放；退树时取消任务。它使用 `Task.Delay` 的真实时间，接入加速模式时要自行核对和 `Cmd.Wait` 的时间尺度是否一致。

阅读入口：[AuraCmd.cs](../artifacts/reference-mods/workshop-vfx-2026-10-14/sources/LovecsVfxLib/LovecsVfxLibCode/Vfx/Auras/AuraCmd.cs)、[PowerAuraController.cs](../artifacts/reference-mods/workshop-vfx-2026-10-14/sources/LovecsVfxLib/LovecsVfxLibCode/Vfx/Auras/PowerAuraController.cs)、[Marker 运行时适配器](../artifacts/reference-mods/workshop-vfx-2026-10-14/sources/LovecsVfxLib/LovecsVfxLibCode/Vfx/Auras/Markers/GdVfxMarkerAdapter.cs)、[强度适配器](../artifacts/reference-mods/workshop-vfx-2026-10-14/sources/LovecsVfxLib/LovecsVfxLibCode/Vfx/Auras/Markers/GdVfxStateReceiverAdapter.cs)。

**适合 Karen 的部分**：力量、闪耀、增益、警告等视觉层共用少量模板，用颜色、数量、速度和贴图区分。当前 `ShineVfx` 已按卡牌模型身份绑定警告节点并在回池时清理，可以借鉴参数配置方法，继续保留现有身份检查。

## 魔理沙的制作流程

### 光束主体直接由 Shader 生成

Final Spark 的场景包含 `MeshInstance2D` 光束、`Sprite2D` 起点星、NoiseTexture 和两份独立 ShaderMaterial。光束 QuadMesh 有细分，Shader 在 `vertex()` 中改变形状，在 `fragment()` 中结合噪声、核心亮度、颜色与彩虹比例；使用 `blend_add` 叠加。

`VfxFinalSpark` 的 C# 状态机依次控制：

```text
Flare 0.3 秒 → Beam 0.5 秒 → Fade 0.2 秒
```

它将 `progress` 写入星与光束材质，在进入 Beam 时震屏。起点使用角色 `VfxSpawnPosition`，方向取目标差向量的角度。尺寸由伤害的对数比例计算，并限幅到 0.5–2，避免按伤害线性放大。

FinalSpark 卡牌在 `AttackCommand.BeforeDamage` 中创建大光束，等待声明的 1 秒，再给每个实际存活敌人加原版 HyperbeamImpact，最后由攻击命令结算。需要区分“画面在 0.3 秒展开”与“规则在等待之后结算”：这套代码不是严格在光束首次到达时扣血。

工坊 DLL 和公开源码的 Final Spark 都有一个明确的自释放问题：Fade 先把进度 clamp 到 `[0,1]`，之后却要求 `progress >= 2` 才 `QueueFreeSafely()`，该条件无法达到。场景本身也没有删除 Timer，因此不能照搬其生命周期；父战斗节点退场仍可删除它，不应据静态代码夸大为永远无法释放。

### 公开工程中的可转向投射物

当前 GitHub 工程还提供 `VfxSparkProjectile`：

- `Damping → Idle → Chasing → FadingOut` 四种状态；可以跳过等待。
- 从剩余时间与目标差计算追踪速度，逐步混合旧方向与新方向，控制到达时点。
- Slug Mesh、Trail Line2D 和 GPU 粒子分开，命中后停发粒子，主体与轨迹继续淡出。
- Shader 的速度、可见度与爆炸进度来自运动状态；1 秒尾部结束后释放。

这适合动态路径和可变距离，与固定长条序列帧的缩放是不同取舍。尾迹长度由运动历史产生，主体形状由 Shader 产生，因此少量纹理即可构成多种弹道。

公开工程的 `StarlitVfx` 还使用旋转椭圆轨道、转向插值和激活爆炸，把持续 Power 表现成可激活的在场对象。该工程与工坊包不是同一版本映射，不能将新工程全部特效都记作已发布或已验证。

## 选择哪条制作路线

| 需求 | 首选路线 | 样本与原因 |
| --- | --- | --- |
| 轮廓复杂且时序固定的少数大招 | 透明 PNG 序列 + 短粒子 | 储君、华丽收场；主运动能直接在美术阶段确定 |
| 持续增益与不同层数 | 粒子模板 + 模型参数 | Lovecs；低资源量、统一生命周期、少量配置形成变体 |
| 多个可数对象、可取消准备状态 | C# 布局与状态机 | 两种储君星环；数量与位置来自真实模型 |
| 远近可变、目标会移动的运输 | Shader 主体 + 实时路径 + Trail | 魔理沙投射物；避免等比拉伸整组素材 |
| 角色出招的速度感 | 短位移与有限姿态残影 | MeleeAttack；能利用角色原有美术 |
| 全屏大招或世界暂停 | 单独的屏幕效果控制器 | MeleeAttack 的影响面较大，需要集中控制并发与恢复 |

PNG 数量和 PCK 大小不能替代性能预算。例如华丽收场 15 张 1920×1080 图，若全部按未压缩 RGBA8 展开约 **118.65 MiB**；储君 Comet 的 70 张 1600×640 图约 **273.44 MiB**。这是尺寸推导的纹理量级，不是测得的显存，也没有计入 GPU 压缩、mipmap、资源共享或其他节点。

## 对 Karen 建议采用的具体流程

1. **先标记真实事件。** 写明出牌开始、实际命中、Power 施加成功、卡牌到达目的地、移除与取消分别触发什么。伤害或收益必须仍由游戏模型与命令决定。
2. **画一条时间线。** 起势、峰值、确认、尾迹各占多久；多击的主动画播一次，每击只播小反馈；快速模式缩短演出，瞬时模式可跳过视觉。
3. **按形状选技术。** 星点与烟使用粒子；灯和光束使用 Shader；复杂固定运动使用透明帧；库存与运输使用 C# 的布局、真实身份和动态路径。
4. **用少量参数产生变体。** 统一颜色、尺寸、强度、起终点和速度接口。独立材质实例，常驻节点有明确 key 与所属模型。
5. **接入正确挂载层。** 角色后方光、前方短冲击、HUD 到达确认分层；坐标来自当前角色、目标和真实容器，不硬编码为单人画面位置。
6. **把清理与建立一起实现。** 每个订阅、Tween、后台任务和滤镜都记录主人；取消、死亡、移除、退树、战斗结束或节点回池时有退出路径。
7. **做针对性实机验证。** 检查普通、快速、瞬时与连续触发；涉及移牌按项目要求保存前后 MCP 截图并执行 `karen_check_hand`。有多人并发的机制再检查各个 Player 的归属与同版本联机。

当前工程已有 Shader 收益流、舞台演出和模型驱动清理，适合进一步收口为少量配置接口。对不同卡牌，先变化运动语义与落点，再调整颜色和粒子数量；无需为了借鉴这些样本立即引入额外 VFX 依赖。

## 解包能恢复到什么程度

五个包都是未加密的 Godot 4.5.1 PCK v3。原始条目提取完成并按 PCK 记录校验 MD5；原始包另记 SHA-256。GDRE v2.7.4 将导入纹理和二进制场景恢复为可读文件，ILSpy 另存 C# 反编译结果。

GDRE 日志中，Marisa 和 MeleeAttack 各有一个转换失败：**随包声明的 Spine GDExtension 原生库不在 PCK 内**。部分音频或导入资源标记为有损恢复，少量 C# 源路径未恢复。已保留原始包与原始提取文件，不能称恢复工程为作者原工程的逐字副本，也不能保证直接在编辑器重新导出即可运行。

三个公开工程与恢复文件中均未找到 AE、Blender、PSD、Houdini、C4D 或 Spine 编辑源工程。这些样本足以分析游戏侧组装流程，**不能确认作者的离线美术软件、原始制作步骤和完整素材来源**。公开仓库中未发现根目录许可文件；后续若复制代码或美术，应另查许可与作者授权。
