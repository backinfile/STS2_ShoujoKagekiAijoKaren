## Result and changes

已实现无等待入场及配套动作、粒子、塔显形和可辨识的亮灯声。声音仅来自既有舞台亮灯采样的校准版；撤掉本次制作的三声合成占位、风切和剑鸣，不加语音。最早的串行方案及中间的合成音试听均已被替换。

### 表现与时序

- `KarenCombatEntrancePatch` 的 `void Prefix` 在 `Hook.AfterRoomEntered` 前创建节点并立即返回；不替换原 Task，不插入等待，不接管转场。原生转场可能遮住部分起势。
- 角色轻移半步、约两度前倾、轻微收势，再回到待机。披风自由边缘产生一次局部风摆，保留原呼吸。仅写 scene-local idle Shader 的入场专用参数，不改原生动画轨道、Sprite2D 位置、颜色、输入或结算队列。
- 原生 AnimationPlayer 开始非 idle 动画时立即取消入场姿态；临时材质或可见性变化同样退出。清理只归零自身入场参数，不重播 idle，不停止原生动画，不替换外部材质。
- 每位华恋共 48 个有限寿命的解析 CPU 粒子：12 个脚边蓝白薄尘、18 个红色披风碎片、18 个剑尖金白碎光。出生后独立运动和衰减，不使用战斗随机数。移除旧三条红线尾迹，剑尖碎光锚点跟随 Shader 姿态。
- 普通模式表现 1.5 秒、快速模式 1.05 秒，与游戏开场并行；瞬时、非交互和 headless 模式跳过。取消和离树清理自身光层、粒子、声音及入场参数。
- 约定之塔在同一时钟内从塔脚向塔尖显形，暖色扫描边缘带动各层灯带亮起，塔尖最后短闪，再回到原有常驻灯光。入场扫描仅裁切原图和调节自身灯光的绘制透明度，不再单独偏移塔、卡牌目标或点击区域，不改约定牌堆状态；三／四人队伍的常驻塔布局适配见下。显形扩展至 age=1.02 秒，让原生转场之后仍能看到塔逐渐出现；演出总时长不增加。
- 战斗初始化原有的 `ClearAll` 会删除旧塔；管理器保留仅限当前房间的表现时钟，在正常牌堆初始化创建新塔时接入当前进度。不会为续播创建新塔、重启演出或改动初始化顺序。召回、虚空和再生产开始时立即取消塔入场；后续帧不重启。

### 灯光声音与参考范围

当前在表现 age=0.18 秒、第一组灯点亮时触发一次 `KarenSfx.EntranceStageLight`，不等待声音结束。资源 `ShoujoKagekiAijoKaren/audio/karen_entrance_stage_light.wav` 取既有 `karen_stage_light.mp3` 的 0.06–1.10 秒，经压缩、5 ms 淡入／40 ms 淡出及峰值校准得到，1.04 秒，44.1 kHz 双声道 PCM，峰值 -1.5 dBFS、RMS 约 -4.94 dBFS。生成方法见 `tools/vfx/entrance/prepare_audio.py` 和资源旁的 CREDITS。播放增益 1.15，独立采样在全音量时的峰值仍约 -0.29 dBFS；快速模式跟随表现倍率变速，能在普通／快速表现结束前播完，中途取消会停止自身播放器。

用户反馈的旧实录确实过轻。实际运行确认游戏 Master／SFX 总线已经应用音量，旧入口又乘了一次 master×sfx；50%／50% 下播放器仅 0.175，两个未静音总线各 -12.04 dB，加上原采样峰值 -15.14 dBFS，亮灯声被战斗混音掩盖。新增 `PlaySfxOnGameBus` 只让原生总线控制用户音量；现有 `PlaySfx` 调用者仍保留原增益，避免顺带改变其他声音。仅加增益的中间版在真实战斗中仍不够清楚，因此对入场专用副本压缩动态范围，没有叠加任何声音。

`check_audio.py` 对游戏进程真实录音与采样作归一化相关及拟合残差检查，而非仅检查音轨不静音。中间版在不同录音中存在混音及匹配波动，最终去除较弱头尾、进一步压缩入场专用副本并将独立增益定为 1.15。测试还发现单一固定采样率模板会把微小重采样差异误算成背景；加入 ±100 ppm（每秒至多 0.1 ms）的时钟误差拟合，相关 ≥0.65、信号／残差 ≥0 dB 的门槛未变。最终正式版相关 0.866、+4.76 dB（时钟比例 1），测试版 0.765、+1.50 dB（比例 1.00005）。旧基线用相同新方法仍为相关 0.057、-24.93 dB，保持失败。旧失败 JSON 仍保留于 `audio-diagnosis`，最终证据存于 `tower-final-master`。指标证明实际录音中存在可辨识采样，不等同于对所有设备的主观听感保证。

该文件与 STS1 老 Mod 的 `Karen_stage_light.mp3` SHA-256 相同（`fc4fc0424d4243d0ba993c856efc1e4bded3f77e6db8b7c6e19ffeacde74a70f`），老 Mod 用它配舞台亮灯。原始录音出处缺少标注，不能据文件名认定为已核实的官方原音。本次没有取得新的官方独立亮灯音频。

### 首轮同版本联机专项（播放范围已由下一节替换）

针对追加的“兼容多人对战”，首轮在现有工作树实现和验证原生同版本联机，不增加网络消息、随机数调用、战斗动作或同步等待。当时每端显示房间中全部华恋的入场，各自持有 scene-local 材质和按 Player 存储的塔时钟；一端选择快速／瞬时只影响本端表现。灯阵共享，亮灯声每端一次，不按华恋人数叠加。用户随后要求只播自己的华恋，当前行为与复测见下一节；此处 16 项保留为此前阶段的证据。

新增每个 `NCombatRoom` 的本地 metadata 标记，重复的表现请求在首次演出中和演出结束后都被忽略；新房间仍可正常播放。压力测试在首次真实入场之外额外请求两次表现，旧版两端均记录到 3 次演出／3 次声音，修复后要求保持 1 次；这是人工重复表现请求的压力场景，未重复执行任何战斗钩子，不能据此认定原生网络一定会重复调用房间钩子。

四人实录发现原常驻塔的后排布局会越过画面上边／左边。三／四人队伍现在将塔缩放为原来的 0.76，并在 viewport/canvas 坐标中为完整图像与计数保留左侧 18、顶部 64 的 1280×720 等效边距；单人和两人沿用原布局。不改变角色站位或卡牌模型，点击区域与塔一同缩放／位移。所有卡牌目标、轨道和交互使用同一塔节点 transform，`TransferCanvasPosition` 同步得到实际甲板坐标，没有独立的过期目标坐标。

工具 `tools/vfx/entrance/verify_multiplayer.py` 为每端提供游戏副本和独立 Mod／用户目录，每例独立存档、日志及端口；KarenSTS2MCP 构建信息确认 loopback-only，MCP 源码目录未改动。游戏运行在未切换到前台的私有测试桌面，所有游戏操作和截图经 MCP/HTTP；未使用 Computer Use。观察 DLL 不进入发布包。声音次数检查记录真实播放器的创建请求，未录制多人混音；可听性实录见前面的单人声音专项。脚本默认静音。
