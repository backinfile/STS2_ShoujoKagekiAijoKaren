## 后台证据

- 通过 Core 巡检使用的只读接口查询线上报错。搜索 `CorePlayerSave`、`KarenRunSaveReadScope`、`RunSaveManager_Patches` 和 `ExtendedSaveHandlers` 均为 0 组。按 Core 2.0.2 复核 58 组记录，候选闪耀异常为常驻特效计算收到 NaN 的既有开发记录，调用栈位于 `NKarenShineAmbientVfx._Process`。原生读档失败的 3 组记录均为旧游戏尝试加载更高版本存档。旧版 `ShineArchive.Entries` 的空玩家预览报错归于 OBS-051，Karen v1.0.2 已含修复。
- 后台可按 Karen 角色查询到 88 份结束对局，筛选 Core 2.0.2 得到 0 份。抽查最近 6 份带 Core 元数据的 Karen 席位，3 份的耗尽堆有《闪耀打击》，1 份的原牌仍在牌组。剩余两份均为 Karen v1.0.0、Core 1.9.5、游戏 v0.113.0 的单人标准胜局，终局牌组和耗尽堆均找不到《闪耀打击》，其中一份的耗尽堆为空。楼层历史未记录该牌的移除或转化，也缺少逐次出牌、存档及重启轨迹，无法还原缺失发生的时点。
- Core 提交 `495ad37` 修复了子结算将待耗尽卡交给已关闭父批次的问题，已包含在 Core 2.0.2 的源码基线。该已知缺陷会留下 0 次闪耀的永久原牌，现场是否同因需要以原局为准。

## 结论与处理状态

当前发布包未复现已保存耗尽档案丢失。能复现的情形是自动保存前关进程后整场战斗回滚，同时恢复耗尽牌和原闪耀预算。若续玩后《闪耀打击》在耗尽堆和永久牌组都找不到，应继续核对原局存档、崩溃日志和版本。两份旧版样本与反馈截图的种子不同。

本提交记录调查和定向验证，业务代码暂不调整。原检出保留 `docs/待修复问题.md` 的未提交删除。
