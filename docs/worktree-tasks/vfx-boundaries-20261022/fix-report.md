# 两项特效缺陷修复

## 用户后续要求

> 修复这两个问题

范围为 VFX-01（深层塔桥过曝）与 VFX-02（Karen 战败返回主菜单时重复断开入场信号）。ENV-01 的来源隔离不属于本次修复结论。

## 实现

- `NKarenBridgeVfx.cs`：每层仍持有独立 Playback、材质、音效和原生出牌任务；同一战斗容器只建立一个 `StageLighting` 节点，以较晚的处理顺序，在各层更新年龄／淡出之后统一归一灯光、粒子及氛围遮罩。单层权重仍为 1；短追光、空堆和 Instant 路径不参与完整舞台预算。所有舞台结束后，亮度节点自行释放，换场由所属容器释放。
- `SNCreatureVisuals.Entrance.cs`：保存订阅时的确切 Callable；退出时检查同一个连接是否仍存在，再断开并清空引用。保留原生攻击动画中断入场姿态的逻辑。

## 负例与中间尝试

- 旧实现重新运行后，八层灯光与遮罩仍直接相加；原生战败返回菜单再次出现不存在连接的断开错误。负例在 `artifacts/vfx-fixes-20261022/red/`；早期选牌索引和 Callable 识别的夹具错误单独保留。
- 首版按节点各自归一，稳态正确，但展开／淡出时读取了本帧和上一帧混合的年龄，逐渲染帧探针捕获遮罩瞬时峰值超过 1；因此改为统一末序处理。两版失败尝试在 `green/attempt1-*`。
- 再次复用测试环境时存档已切换成铁甲战士，Karen 专用基础夹具缺少预期塔节点，导致 IntegrationWatch.get_Tower 的 Sequence contains no elements 和 HTTP 500。这些不是已执行出牌的兼容性失败；该轮保留于 `green/`。最终改用原始有效 Karen 快照新建 `final/`，不把无效前提当作通过。
- 燃烧会升级从约定取出的内层塔桥，使其各自预留两张牌。七张内层塔桥在该规则下只能形成五层有牌舞台；补充场景使用十三张内层塔桥，验证实际达到八层，而非把正常预留规则误判成生命周期缺陷。
- 原生主菜单命令需要运行中战局，重开局夹具改为在新战局可用后重置入场观察器；Why 移牌后重新读取当前可选索引。所有失败尝试均保留，不覆盖旧日志。
