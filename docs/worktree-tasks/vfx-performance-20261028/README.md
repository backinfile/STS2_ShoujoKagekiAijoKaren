### 修改与原因

- `src/Core/Vfx/KarenVfxCanvasBatch.cs`：复用顶点、颜色、索引及按需 UV 缓冲，把有序的小图元合并提交；保留线条的透明抗锯齿边缘。普通/临界闪耀、塔灯、金蓝回手尾迹与燃烧卡面共用此入口。
- `NKarenShineAmbientVfx`：移除四段游走边线，保留柔和轮廓、顶部星光与少量星点。`NKarenShineWarningVfx` 的临界提示继续显示。
- `ShineCardBorder`：轮廓或相对变换改变时再更新几何；回手尾迹每帧复用采样位置与视口比例，继续跟随原生卡牌节点。
- `ShineVfx.WillDeplete`：先判断耗尽条件，再读取动态 Keywords。高闪耀牌省去每次约 2032 字节的关键词查询分配，临界牌继续实时查询；58 项规则回归通过。
- `NKarenBurnCardVfx`：原可见性条件只接受 Hand；改为实际可见卡牌处于 Hand 或 Play 时显示，保留离开这些牌堆后的停止流程。
- 新增 `NKarenBurnCardParticleLayer`：同一套火花/烟雾贴图、发射间隔、锚点、颜色和运动方程，改用托管粒子状态和每卡两次纹理批绘制。十张燃烧牌约 250 个卡面 Sprite2D 粒子节点变为 20 个绘制层；角色及塔上的原燃烧粒子保持原实现。
- `KarenVfxWarmup` 实际绘制新增图元和纹理四边形，沿用等待渲染完成与 finally 清理；更新 owner 登记和生成清单。资源清单检查为 72 类型、38 共用 owner、167 资源。
- 新增测试命令 `tools/promise-transform/BurnCardVfxCmd.cs`：准备真实 Burn→Tower→Fall 流程，逐帧观察打出区火焰，检查消耗后清理。该工具属于独立测试插件。

### 本机性能对照

Windows x64 / RTX 4060，1920×1080，关闭垂直同步与帧率限制，Normal 动画速度；每组从新进程进入 Karen 战斗，固定十张牌与操作。下表是 ProcessFrame 墙钟间隔中位数（ms）。普通测试开局的背景和敌人由游戏随机生成，驱动缓存保留；录像另用同一开局存档。主要开销来自闪耀牌、塔灯的大量小绘制与重复动态查询，觉醒本身的风效占比较低。

燃烧专项的“前”使用仅完成闪耀/塔优化的中间包，以隔离卡面粒子变化。正式版十张燃烧牌帧间隔中位数 2.010→1.890ms；同进程暂时隐藏卡面火焰的对照差为 0.319→0.210ms，绘制调用增量约 157→29。该专项整体帧耗时改善约 6%，主要收益是降低卡面节点与绘制开销。测试版最终包为 1.900ms，隐藏火焰对照 1.686ms。
