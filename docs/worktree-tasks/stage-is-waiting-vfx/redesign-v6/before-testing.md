## 最终原声视频

使用 <karen-sts2-mcp-source> 的当前 70c9dc2 源码，分别对两版构建并仅安装到本任务录像副本。机制专项原始记录保留不覆盖；最终展示另行重录。DLL / PCK 哈希与当前正式包一致。

- 正式版实际采帧：29.24 fps；测试版：29.58 fps。均使用 h264_nvenc，音频来源为 game_process。
- 八秒时钟审计各解码 240 帧，分别 239 个不同时间值；最长重复 0.067 秒；时间轴偏差分别 0.006667 / 0.003333 秒，丢帧 0。
- 交付合片 46.881 秒，只在原始 1280×720 游戏画面下方添加说明条，保留游戏进程声音。未检出超过一秒的冻结。见 media-summary.json。
- 双版本有牌、空堆、补牌与触发帧从最终重录视频抽取，时间、原文件哈希和机制观察见 state-frame-evidence.json。
- 四个本任务隔离进程已退出，18817/18818/18827/18828 端口关闭，配置逐字节恢复，临时观察器移除；未更改共享开发游戏、Steam 安装或别的 Mod。

## 证据与复现

完整机制证据：artifacts/stage-is-waiting-film/{stable,beta}/；
最终录屏与时钟证据：artifacts/stage-is-waiting-film-video/{stable,beta}/。
正式验证报告：verification.json；录像构建与 MCP 来源：media-summary.json。

运行工具为 tools/vfx/catalog/prepare.py、record.py、verify_waiting_stage.py 和 package_waiting_stage.py。
verify_waiting_stage.py 的 --media-output 指向另行重录的交付目录，既检查机制 / 生命周期证据，也检查当前 MCP 的实际录屏和日志。record.py 的 --audit-capture 仅安装在临时观察器中，不进入正式 Mod。

首轮两处旧断言不符合新设计：收束三行灯束的最大总宽是 60；已打开或连续触发保持展开时不需要再次扫过全角度。已修正为逐场景检查，同时保留正常有牌打出时的扫动距离检查。失败尝试保存在本地 artifacts，不算通过案例。
