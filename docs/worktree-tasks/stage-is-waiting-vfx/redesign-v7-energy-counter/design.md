# 能量槽承接常驻状态：设计预览

用户新要求：

> 不要胸前两态光缝，这个状态重新设计下

> 你看看是不是可以直接设计到能量展示槽那里？

## 判断与方案

可以。能力实际结算就是清空约定牌堆后获得能量，把状态放在现有能量槽外缘，能让“候场→兑现→待续”围绕真实资源反馈展开，并避开角色与约定之塔。

这是内置 imagegen 生成的设计预览，不是实机；当前运行代码仍为上一版，尚未将此图的表现接入游戏。输入为已直接查看的真实有牌与回能截图，完整提示词见 imagegen-prompt.json。

| 状态 | 能量槽表现 | 约束 |
| --- | --- | --- |
| 有牌候场 | 暖金细光沿现有左下轮廓收聚，保持低亮 | 灯光形状与数量不编码牌数，不改能量数字 |
| 清空且实际回能 | 右上短距离细粒子向外缘汇聚，局部闪光，随后退去 | 只有实际增能才触发；数字仍由原有能量模型驱动 |
| 空堆待续 | 上右外缘保留安静的冷白低亮边光，极少浮尘 | 不重复聚光、回能声音或数字跳动 |
| 补牌 | 从冷白待续平滑回到暖金候场 | 不假造一次能量获得 |

常驻仅超出现有能量槽约 15 像素，瞬时光流控制在附近约 55 像素。胸前光缝、环形胸饰、腹部光球均撤出新方案；不把旧光缝平移到 UI。

## 接线调查

- scenes/combat/energy_counters/karen_energy_counter.tscn 已有 Control、前后粒子层和独立 Label。
- SNEnergyCounter 继承 NEnergyCounter，当前能量变化已有 MyEnergyVfxFront／MyEnergyVfxBack 和原生 burst。
- 能量槽状态层应跟随本地玩家真实 NEnergyCounter 的 UI 变换，位于数字后方或仅绘制外缘；鼠标穿透，不改 Label、能量或最大值。
- 可以沿用当前 Power 的真实牌堆状态刷新与实际增能确认，避免用能量数值变化反推本能力触发。
- 与原有星屑回能反馈错峰，避免同一时刻增加第三组耀眼爆发。
- 非本地玩家没有对应的本地能量槽，不能误绑到本地计数器；没有有效 UI 时跳过此常驻层。
- 后续实装仍需验证分辨率／UI 缩放、能力叠层、连续触发、补牌、快速／瞬时及释放清理，不能把本次预览当作实测结论。
