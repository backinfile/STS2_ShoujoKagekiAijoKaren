常规移牌用例均保存 MCP 前后截图，并执行 `karen_check_hand`：模型/节点数量一致，无 missing/unexpected 或多余牌堆图标。已实际查看核心前后画面和录像抽帧。清场专例仅保留参与结算的两张牌，最终诊断为 0/0。

### 不能合并为“全绿”的诊断

- 最初清场夹具额外保留了一张防御；到奖励页，原生模型清空，但 `ActiveHolders` 仍包含隐藏防御。`karen_check_hand` 统计 ActiveHolders 而未过滤 `IsVisibleInTree()`，因此返回 0/1。保留了失败记录，未据此修改游戏或伪报通过；两张参与牌的清场专例最终 0/0。
- 测试版在“删除表现节点后，继续用 `fight` 开发命令跳入新战斗”的同进程序列出现 `NCard ... already been freed` 原生回池诊断。各用例的伤害、奖励、移牌检查仍通过，但这组日志不能称无错误。新特效不接管/释放 NCard；未充分定位该诊断的因果，未擅自修改通用池或原生卡牌流程。
- 无特效的 Instant/不可打出对照中，测试版启动时出现一次 Godot `Invalid Task ID`，发生在主菜单资源预加载阶段，先于出牌。该对照未出现上述 NCard 回池诊断。
- 第一轮测试探针曾因两版共享 `obj` 混用程序集引用而失败；探针现按 Variant 隔离中间产物。重测使用正确版本。
- 一次独立测试版清场录像在出牌前由 MCP `Texture2D.GetImage` 报内存分配失败并断连。改为无连续录像的截图/逻辑检查后，独立清场通过，日志无 ERROR/Exception；常规九次演示录像已正常完成。
- 未测多人、其他分辨率、所有其他 Mod 组合，以及全量卡牌矩阵。

## 视频质量

成片约 19.62 秒，1280×784 / H.264 / 30 fps / AAC。原游戏视口 1280×720 完整保留，上方仅增加标题带；正常 9 次与快速 3 次直接拼接，没有后期添加特效。只对播放音量加 9 dB，原始片段未改。
