证据保存在播放器目录的 `evidence/`，包含逐项结果、实际手牌检查、截图、两端日志、录屏信息和构建哈希。机器可读汇总见 [validation-summary.json](../../../artifacts/seven-card-vfx-showcase-20261013/validation-summary.json)。

- 蛋糕成功时只接力一次原生药水飞行，形成点与原生图标中心误差为 0；满药水栏时没有新增药水和假成功高潮。
- 什锦和晚餐分别增加实际力量 8，升级后 10；临时力量回合结束消退，永久力量保留。
- 实际打出坠落，将升级什锦送入约定牌堆；回合结束变成升级晚餐。梦想同时生成真实光辉，门票在下回合生成真实约定之塔。
- 实际打出约定之塔，晚餐与光辉进入真实手牌。截图中约定星点从 2 变为 0，手牌模型与可见节点一致。
- 随后实际打出光辉，能量从 0 变为 2；升级案例从 0 变为 4。火花数匹配实际增量，落点使用本地 NEnergyCounter。Fast、Instant、提前取消均通过。
- 双人两端各观察到一次共同演出、两个真实受益者；双方战后各有一项 `special_card` 奖励。演出不会预先伪造随机奖励牌面。
- 全部测试进程位于隔离 Windows 桌面，前台占用采样为 0。只通过 MCP 操作游戏，未使用 Computer Use，也未更新 Steam 或主工作区开发 Mod。

## 构建与日志边界

任务实现提交为 `1bb25ac`。随后在任务分支中同步 `main` 的 `fae5a13`（七件遗物提交），无冲突；最终再次完成双版本构建和两版各 19 项实测。主工作区原有六份文件的 SHA-256 均保持原样，任务尚未合并回 main。

33 项边界中的测试版构建早于最后一处 Void 模式落点保护：在抽牌堆模式下改用真实牌堆锚点，避免请求不属于约定堆的星点。正式版 33 项已包含此保护；同步后的两版 19 项使用最终 VFX 代码。此次没有另测 Void 专项，不把普通约定路径的结果扩展为全模式验收。

主成片采用同步 main 前的正式版录屏，七牌 VFX 与同步后的代码、贴图和 Shader 相同；同步后的两版证据另外保存。各阶段构建哈希分别记录，不冒称全部录像来自同一个二进制包。

所有验收套件的 `unexpectedErrors` 都为空。测试版启动阶段仍可能出现基线已有的 `ERROR: Invalid Task ID`，逐项数量单列在汇总中；这不是所有日志零错误的结论。只在首次出牌之前识别该精确诊断，其他运行错误会令测试失败。

早期迭代发现丝带多边形错误，已改为明确三角形绘制并复验；一次正式版录屏捕获超时已重新录制成功。早期脚本还因重复注入同 ID 晚餐而选错夹具，现已在边界测试前清理手牌，Instant 校验改为实际张数减少与结果生效。失败轮次保留在工作树 artifacts 中，未计入通过结果。
